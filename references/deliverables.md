# Deliverables

以下结构按任务裁剪。每份交付物都应明确结论、取舍、owner、指标和风险。

## 1. 产品方案 / PRD

1. 背景、问题和证据
2. 目标、非目标、用户与场景
3. 现状链路和主矛盾
4. 方案总览与核心机制
5. 关键流程、状态和边界条件
6. 运营、数据、治理及人机分工
7. 指标、埋点、评估和灰度
8. 依赖、里程碑、风险与回滚

写清为什么是这版范围，以及哪些问题不由产品功能解决。

## 2. 增长或留存方案

1. 阶段判断、目标人群和北极星指标
2. 漏斗与 cohort 诊断
3. 增长或留存机制
4. 渠道、内容、产品和运营分工
5. 实验假设、优先级和样本要求
6. 收益、成本、回收期和反指标
7. 复盘周期与停止条件

留存未验证时，不给激进拉新建议。

## 3. 产品运营 / 平台治理方案

1. 生态角色、目标行为和主要矛盾
2. 现有规则、激励、分发和风险
3. 分层、权益、触达、治理与申诉机制
4. 产品能力与人工运营的边界
5. 质量指标、生态指标和异常预警
6. 推进节奏、owner 和复盘机制

说明哪些人工动作会沉淀成可复用能力。

## 4. 标准、标签或流程体系

1. 服务对象及其关键决策
2. 当前口径差异和业务损失
3. 定义、边界、分类、示例和冲突规则
4. 生产、审核、发布、消费和变更链路
5. 覆盖率、一致性、准确性、时效性和采用率
6. 与业务结果的传导关系
7. 责任矩阵、版本机制和退场条件

避免只交付静态文档；体系必须被流程或系统消费。

## 5. AI Agent 工作流改造

1. 当前任务链、成本、质量和风险基线
2. 适合与不适合自动化的节点
3. agent 所需上下文、工具、权限和记忆
4. 人机交接、审批、升级和兜底
5. 离线评估集、在线指标和失败样本闭环
6. 成本、时延、质量、采用率和净收益
7. 小流量试点、扩量门槛和回滚方案

把“能生成”与“能稳定承担业务责任”分开。

## 6. 商业模式或竞品分析

1. 业务定义、核心用户和价值交换
2. 收入来源、成本结构和单位经济
3. 增长飞轮、留存机制和供给控制点
4. 用户体验、生态和合规边界
5. 对手战略意图、优势、约束和窗口期
6. 我方差异化、关键下注和止损条件

不要做没有决策结论的功能表格。

## 7. 内部价值 / OKR 论证

1. 要解决的经营或组织问题
2. 基线、反事实和受益对象
3. 产出 -> 采用 -> 行为变化 -> 业务结果
4. 主导成果、共同贡献和不可归因部分
5. 领先指标、结果指标、反指标和目标值
6. 季度动作、关键依赖和证据采集方式

用可信贡献替代夸大的“直接创造价值”。

## 8. 高层汇报 / 战略 Memo

1. 核心结论与决策请求
2. 当前阶段、主矛盾和证据
3. 为什么是现在
4. 推荐方案、替代方案和取舍
5. 预期结果、资源和时间
6. 关键风险、前提和退出机制

使用经营语言，页面与执行细节放附件。

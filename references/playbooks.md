# Playbooks

以下打法用于高频场景。先选择最接近当前问题的一项，再按业务事实调整。

## 1. 0-1 产品立项

1. 定义目标用户、非目标用户和高价值场景
2. 识别替代方案、迁移成本和最小价值主张
3. 设计最小闭环，而不是最小功能集合
4. 准备冷启动供给或人工补位
5. 验证首次价值、第二次使用和真实付出
6. 设成功阈值、止损条件和下一阶段门槛

必须回答：为什么值得做、为什么从这里切入、用户为什么回来、最可能死在哪里。

## 2. 留存下降诊断

1. 区分新用户与老用户、全量与局部问题
2. 按渠道、版本、人群和 cohort 定位变化
3. 检查首次价值、供给质量、分发和打扰
4. 回看商业化、规则、算法或组织变更
5. 建立原因优先级，先验证最大影响假设

不要用活动拉活掩盖产品价值下降。

## 3. 双边平台冷启动

1. 明确先打哪一边以及原因
2. 选择最易闭环的城市、品类或场景
3. 用运营补足早期系统能力
4. 优先保证匹配、成交或履约成功率
5. 沉淀评价、规则、申诉和供给分层

没有供给质量不放大需求，没有履约保障不放大品牌。

## 4. 平台增长与治理

1. 定义核心关系、核心内容或交易单元
2. 检查供给、分发、互动、激励和商业化是否一致
3. 识别作弊、骚扰、低质和逆向选择
4. 联动正向激励、处罚、解释和申诉
5. 同时监控规模、质量、公平和长期生态指标

治理不是事后审核，应进入分发、权益和商业化机制。

## 5. 标准、标签与流程体系

1. 从真实业务决策出发，列出标准的消费方
2. 量化口径不一致造成的返工、误判、风险或机会损失
3. 设计定义、边界、例外、示例和冲突优先级
4. 建立生产、审核、发布、使用、反馈和变更闭环
5. 追踪采用率、一致性、准确性、时效性及业务结果
6. 把高频稳定部分产品化，把争议判断保留给人

没有消费方和行为变化的标签体系，应合并、停更或下线。

## 6. AI Agent 工作流改造

1. 画出当前任务链及成本、耗时、质量和错误类型
2. 选择高频、可拆解、可评估、错误可恢复的节点试点
3. 补齐上下文、工具、权限、记忆和结构化输出
4. 定义人审阈值、升级条件、日志、回滚和安全边界
5. 用真实历史样本建立离线评估，再做小流量在线试点
6. 以净节省、质量、时延、采用率和异常率判断是否扩量

优先改造端到端闭环中的瓶颈，不追求 agent 数量。

## 7. 商业化评审

上线前检查：

1. 是否伤害核心用户体验或供给积极性
2. 收入提升是否可持续，单位经济是否健康
3. 是否诱发低质内容、商家或行为
4. 是否有分层、频控、灰度和回滚
5. 长期信任损失是否超过短期收益

优先选择与用户价值和供给升级协同的变现。

## 8. 竞品反制

1. 判断对手在抢用户、供给、入口、数据还是心智
2. 找到其增长引擎、资源禀赋和关键控制点
3. 识别其成本、组织、生态或商业模式约束
4. 选择正面竞争、侧翼切入或差异化错位
5. 用我方最强杠杆攻击可改变的薄弱点

不做情绪化全面跟进，也不抄没有机制支撑的表面功能。
